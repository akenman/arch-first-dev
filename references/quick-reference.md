# arch-first-dev 速查表

## 触发

```
"用 arch-first-dev"           → G3 完整流程
"用 arch-first-dev 设计接口"   → G1 行为契约
"用 arch-first-dev 约束检查"   → G2 约束驱动
"先设计再写代码"               → G3
"架构不合理/代码太零散/逻辑有漏洞" → 自动触发
"屎山/祖传代码/历史包袱/不敢动"  → 屎山模式（legacy-mode.md）
```

## 屎山模式速查（legacy-mode.md）

```
五步: 考古(不改代码) → 安全网(特征测试) → 选缝(防腐层) → 绞杀迁移 → 收尾展望
规模护栏: >50 文件禁全读；单次考古读文件 ≤30；依赖图用工具不靠通读
影响面四问(改动前强制): ① 谁依赖我(fan-in) ② 我依赖谁(fan-out)
                        ③ 波及面有无无测试区(有先补特征测试) ④ 偿还/新增 @DEBT 哪笔
@DEBT 台账: 位置/类型/证据/影响/偿还计划/状态[open|repaying|retired]
童子军受控版: 每迭代最多还 1-2 笔相关债，顺手修必须记 @CHANGE 并销账
```

## 粒度选择

| 粒度 | 适合 | 产出 |
|------|------|------|
| G1 | 接口设计/Review | pre/post/error/side-effect |
| G2 | 重构/接口检查 | G1 + 7 约束 + 最小蓝图 |
| G3 | 新项目/大型重构 | 完整蓝图 → 填充 → 验证 |

## 7 条约束

```
1. 蓝图未确认 → 不写代码（微项目档：知会即续）
2. 一次一格（同层可并行；微项目/简化档同层 ≤3 可批量填充）
3. 依赖先填
4. 变更有痕（@CHANGE）
5. 模块边界（只走接口）
6. 接口有消费者
7. 只读接口签名
```

## 3 个 Phase

```
Phase 1: 画蓝图
  ①实体→@DATA ②行为→@FLOW ③模块→@MODULE ④依赖 ⑤排序→@BUILD_ORDER ⑥覆盖率 ⑦用户确认

Phase 2: 逐格填充
  定位→加载→实现→验证→标记→确认→收尾

Phase 3: 连通验证
  ①流验证 ②依赖检查 ③边界检查 ④错误链 ⑤空位检查 ⑥变更回溯 ⑦运行时验证 ⑧生成SUMMARY ⑨回顾
```

模块状态
```
[empty]       → 待实现
[in progress] → 实现中
[done]        → 已完成
[deferred]    → 延迟到后续版本
[wontfix]     → 已知但不修复
[removed]     → 已废弃删除
```

## 三档规模模式（v2.3，validate_blueprint.py 自动判定）

| | 微项目（≤8接口） | 简化（9-15接口） | 完整（>15接口） |
|---|---|---|---|
| 确认门 | 知会即续 | 阻塞确认 | 阻塞确认 |
| 同层批量填充 | ≤3 允许 | ≤3 允许 | 不允许（一次一格） |
| 测试 | 仅跨模块接口 | 每接口 happy-path | 接口+边界+错误链 |
| CHECKPOINT | 仅 Phase 切换 | 每 [done] | 每 [done] |
| validator 复检 | 蓝图未改则跳过 | 蓝图未改则跳过 | 预检+复检 |
| 边界矩阵 | 可省 | 可省 | 全量 |
| @ERROR_CHAIN | 0-1 条 | 1-2 条 | 全量 |
| 逐行对照 | 跨模块全量+内部抽查 | 全量 | 风险导向 |
| Phase 3 | ①⑤⑥⑦+⑨ | ①⑤⑥⑦+⑨ | ①-⑨ |

## 契约修复三要件（跨模块数据/行为不一致时的修复质量判据）

```
默认: 在数据属主（生产者）读写边界单点规范化，消费方自动对齐
三要件: ① 属主边界收口（或说明理由）② 消费方零改动/有契约依据
        ③ @DECISION 点名被否决的另一条路径
逆向蓝图: G2/修 bug 场景只对受影响 @FLOW 上的模块局部逆向（@META 标 scope: partial）
```

## 蓝图结构

```
@META → @PROGRESS → @MODULE → @FLOW → @DATA → @BUILD_ORDER
→ @CROSSCUT → @EXTERNAL → @ERROR_CHAIN → @DECISION → @CHANGE
```

## BEHAVIOR 声明

```
完整: pre + post + error + side-effect
纯函数: 只写 post
UI组件: post + side-effect
配置声明: 只写 post
写文件接口: 必须声明父目录不存在时的行为（自动创建/报错）
数值格式化: 必须指明舍入模式（如 half-up），"四舍五入"不可测
```

## 契约修复优先序（跨模块数据/行为不一致时）

```
默认: 在数据属主（生产者）读写边界单点规范化，消费方自动对齐
例外: 消费方就地修补仅限 hotfix（≤2 文件）且必须记 @DECISION + 收敛计划
逆向蓝图: G2/修 bug 场景只对受影响 @FLOW 上的模块局部逆向（@META 标 scope: partial）
```

## 上下文压力信号

```
🟢 无信号 → 正常
🟡 推理步数增加 → 跳过非必要蓝图重读
🟠 旧内容回流/错误重复 → 释放已完成代码
🔴 频繁读蓝图 → 压缩上下文
🟠+🔴 → 写CHECKPOINT，建议新会话
```

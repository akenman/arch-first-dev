# 屎山模式（Legacy Mode）

> 加载条件：任务对象是祖传/无文档/腐化的存量代码（用户说"屎山/祖传代码/历史包袱/不敢动"），
> 或逆向蓝图时发现腐点密度高（循环依赖、上帝文件、越界调用、测试缺失）。
> 核心立场：**在屎山里，最大的风险不是改得慢，而是改得局部**——你看到的每一行都连着
> 你没看到的东西。本协议的全部设计都服务于两件事：看清整体（影响面），留好后路（台账与接缝）。

## 五步协议

```
1. 考古（不改代码）→ 现状地图 + @DEBT 台账
2. 安全网 → 给目标区域补特征测试，先固化现状行为再动刀
3. 选缝 → 从 @DEBT 台账 + 影响面选下刀位置，一次迭代只开一个缝
4. 小步迁移 → 绞杀者路径（见 patterns.md @PATTERN strangler），每步跑安全网
5. 收尾展望 → 影响面 diff 报告；台账更新；下一次迭代的偿还建议
```

### 第 1 步：考古（Anthropology，不改任何代码）

目的：建立"现状地图"（`scope: partial` 蓝图）+ 腐点台账，替代"哪里出问题读哪里"的局部视角。

规模护栏（硬规则，违反即停）：
```
- 文件数 > 50：禁止全量读取。先目录树 + 入口文件 + 配置/依赖清单，再按需下钻
- 依赖图用 scripts/archaeology.py 构建（Python/JS/Go；范围外用 grep import/require/use、
  pydeps/madge/jdeps），不靠逐文件阅读
- 读任何文件前先问：它在我要改的子图里吗？不在 → 只记路径，不读内容
- 单次考古读取文件数上限 ~30；必须超出时，先向用户汇报当前影响面再扩大 scope
```

考古产出：
```
1. 依赖图（谁 import 谁；标出循环依赖与扇出 top5）
2. 热点清单：git log 频率 × 文件大小/圈复杂度——最常改又最难改的地方
3. @DEBT 台账（写进 BLUEPRINT.md，格式见下节）
4. 现状地图：只覆盖"本次任务涉及的子图 + 直接邻居"的 scope: partial 蓝图
   （沿用逆向蓝图 8 步，但范围受护栏约束）
```

框架惯例识别（考古提速：有框架就用框架的模块边界，不要自己发明）：

| 框架 | 模块边界 | 接口识别 | 备注 |
|------|---------|---------|------|
| Django | app/ 即模块 | urls.py 路由 + models.py + 对外 service 函数 | settings 归 @CROSSCUT |
| FastAPI/Flask | router/蓝图文件即模块入口 | 路由函数 + 依赖注入声明 | pydantic schema 即 @DATA |
| NestJS | *.module.ts 即模块 | provider/controller 导出 | DI 容器即依赖图 |
| Spring | @Service/@Component 所在包 | public 方法 + 接口 | application.yml 归 @CROSSCUT |
| Go | 目录 = package | 导出函数（大写） | go.mod 即依赖清单 |
| Rails | app/models 等目录约定 | controller action + model 方法 | 路由文件即 @FLOW 索引 |
| React/Vue 前端 | 页面/feature 目录 | 导出组件 + store action | API 层通常是 @EXTERNAL 消费方 |

### 第 2 步：安全网（先测后改，与常规测试策略方向相反）

改屎山的黄金法则：**没有安全网不动刀**。给将要改动的区域补**特征测试
（characterization tests）**——把现状行为固化下来，包括怪异行为：

```
- 特征测试断言的是"现在是什么样"，不是"应该是什么样"
- 发现的怪异行为：记入 @DEBT（类型: 行为可疑），不在本轮"顺手修好"
- 安全网未覆盖的波及面区域 → 先补测试，再进入第 3 步
```

### 第 3 步：选缝（在整体中选下刀位置）

缝 = 新旧代码之间的稳定接口。候选（按优先序）：
```
1. @DEBT 台账中与本次任务相关的腐点（还债顺便完成任务，一石二鸟）
2. 现有测试覆盖最好的边界（安全网现成）
3. fan-in 低但腐化重的模块（波及面小，收益大）
下刀方式：@PATTERN legacy-seam（防腐层）包住腐化点，新逻辑只依赖 seam 接口
一次迭代只开一个缝——同时开多个缝 = 同时承担多份回归风险
```

### 第 4 步：小步迁移（绞杀者，见 patterns.md @PATTERN strangler）

```
- 新实现在 seam 后面与旧实现并存，按功能单元逐块切换
- 每步：安全网全绿 + validate_blueprint.py 通过 + 项目质量门通过
- 旧实现退役必须显式：状态 [removed] + @CHANGE（禁止"先留着以后删"）
```

### 第 5 步：收尾展望（放眼未来的落点）

```
- 影响面 diff：改动前后的签名快照 diff（SIGNATURES.json）+ 依赖图 diff
- @DEBT 台账更新：retired / repaying / 新发现的腐点全部入账
- 给下一次迭代的偿还建议（写入 SUMMARY.md ⑨ 回顾）：
  "本次开了 orders 缝，台账中 payments 腐点与之同构，建议下次复用同一缝式"
```

## 影响面报告（改动前强制——"不局限于局部改动"的机制）

任何跨模块改动动刀前，必须能书面回答四问（记入 @CHANGE 的「影响」字段）：

```
1. 谁依赖我要改的符号？（fan-in 清单，用 scripts/archaeology.py --impact 验证，不许凭印象）
2. 我要改的东西依赖谁？（fan-out 清单）
3. 波及面里有没有无测试覆盖的区域？（有 → 先补特征测试，回到第 2 步）
4. 本次改动偿还 @DEBT 的哪一笔？或新增了哪一笔？（不答 = 无视整体，违规）
```

答不出第 1 问 → 回到考古。四问全过才允许进入实现。
非屎山项目做跨模块改动时，此报告同样建议执行（轻量版：只需 1、4 两问）。

## @DEBT 台账格式（写进 BLUEPRINT.md；validator 机械校验必填字段与状态枚举）

```
@DEBT_001
  位置: src/orders.py（上帝模块：58 个函数，被 12 个模块 import）
  类型: 上帝模块
  证据: fan-in 12 / 零测试覆盖 / 函数平均 80 行（可验证的事实，不是印象）
  影响: 任何改动波及 12 个消费方；回归风险高
  偿还计划: 分三次迭代绞杀迁移至 orders/ 子包（下次先提取支付路由）
  状态: [open]
```

`类型` 枚举：上帝模块 | 循环依赖 | 越界调用 | 死代码 | 魔法常量 | 行为可疑 | 无测试热区。
`状态` 枚举：open | repaying | retired。必填字段：位置 / 类型 / 证据 / 影响 / 状态；
缺失或非法由 validate_blueprint.py 报 E_DEBT_* 错误（fan-in 数字用 scripts/archaeology.py 取证）。

台账纪律：
```
- 考古发现的所有腐点必须入账（含本轮不处理的——可见即可，不强迫本轮还）
- 童子军规则（受控版）：每次迭代最多偿还台账中 1-2 笔与本次改动相关的债；
  顺带修复必须记 @CHANGE 并在台账销账——"顺手修"但无台账记录即违规
- 状态流转：open → repaying（本迭代在还）→ retired（已消除，附 @CHANGE 编号）
```

## 与主流程的衔接

```
- 考古产出的现状地图 = scope: partial 蓝图 → 后续走迭代模式（v2.2 局部逆向即出于此）
- 安全网测试 = 测试策略的反转变体（先测后改）
- 契约修复三要件、漂移检测、三档规模模式全部照常适用
- Phase 3 ⑦ 优先跑项目已有质量门；屎山项目通常没有——特征测试就是它的第一道质量门
- 完成判据：不是"改完了"，而是"改完后，影响面内的行为有安全网保护、台账如实更新"
```

## 何时不用本模式

```
- 存量代码结构清晰（有文档、有测试、模块边界健康）→ 直接走迭代模式 + 局部逆向
- 用户明确"只许最小改动，别的不许碰" → 跳过第 3/4 步的结构动作，但影响面四问
  与 @DEBT 台账仍然强制（这是对"别碰坏"承诺的落实方式）
- 绿地项目 → G3 正常流程
```
